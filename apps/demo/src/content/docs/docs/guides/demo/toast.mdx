This example follows the core behavior of the
[Base UI Toast specification](https://base-ui.com/react/components/toast): a
manager creates notifications, a viewport owns their stack, each notification
can close itself, and a default timeout removes it automatically. The demo caps
the visible stack at three notifications.

`FloatingPresenceStack` owns the framework-neutral lifecycle. The Web Component
adapter, `floating-presence-stack`, also owns template cloning, value binding,
transition presence, raw stack state, and final DOM removal. Application code
owns pause/resume triggers and keyboard focus policy; application markup and CSS
own semantics, layout, and appearance. The same element can therefore render
banners, transient editors, or other delayed-removal surfaces without becoming
a Toast component.

The Web Component example needs no list or composite wrapper. Native buttons
already participate in the document's Tab order, while `F6` moves focus to the
newest notification's close button. Vue exposes the same controller methods
through `useFloatingPresenceStack()` and adds reactive state for template
rendering.

```html
<floating-presence-stack
  class="toast-viewport"
  role="region"
  aria-label="Notifications"
  aria-live="polite"
>
  <template slot="content">
    <article class="toast-item" role="status">
      <strong data-presence-text="title"></strong>
      <p data-presence-text="description"></p>
      <button type="button" data-presence-close>Dismiss</button>
    </article>
  </template>
</floating-presence-stack>
```

```ts
const viewport = document.querySelector("floating-presence-stack");
viewport.configure({
  limit: 3,
  timeout: 5_000,
  exitDuration: 220,
  topLayer: "popover",
});

viewport.add({
  title: "Saved",
  description: "Your changes have been saved successfully.",
});

viewport.addEventListener("pointerenter", () => viewport.pause("pointer"));
viewport.addEventListener("pointerleave", () => viewport.resume("pointer"));
```

`configure()` accepts a partial object, so behavioral values stay with the
application's JavaScript configuration. Assigning `viewport.options = {...}`
is equivalent. The `limit`, `timeout`, `exit-duration`, and `top-layer`
attributes remain a static-HTML fallback; explicit code options take
precedence. Keep landmark and live-region attributes in markup because they
describe the rendered region rather than behavior configuration.

Vue receives the same lifecycle API without a component wrapper:

```ts
const notices = useFloatingPresenceStack<ToastContent>({
  limit: 3,
  timeout: 5_000,
});

notices.add({title: "Saved", description: "Your changes were saved."});
notices.pause("pointer");
notices.resume("pointer");
// Render notices.records.value; call notices.remove(id) after CSS exit.
```

For a fixed Vue surface that should participate in the browser's native Top
Layer, pair the presence lifecycle with `useFloatingTopLayer()` on the element
you render. This keeps the API parallel with `top-layer="popover"` on the Web
Component while leaving the element's markup and CSS in application code:

```ts
const surface = ref<HTMLElement | null>(null);
useFloatingTopLayer(surface, computed(() => record.open), {
  kind: 'popover',
});
```

## Interaction contract

- A notification remains for five seconds by default.
- Hovering the viewport or moving keyboard focus into it pauses every active
  timeout; leaving resumes the remaining duration rather than restarting it.
- The stack expands while paused so covered notification content becomes
  readable.
- The close button starts an exit transition. DOM removal occurs after the
  transition finishes.
- The viewport is a labelled landmark with polite live announcements. `F6`
  moves focus to the newest close button without taking focus when a
  notification first appears; Tab continues through the remaining controls.
- `template[slot="content"]` follows the same declarative surface contract as
  `floating-root`. With `topLayer: "popover"`, every cloned notification uses
  the native manual Popover API. Dialog is intentionally avoided because a
  Toast must not trap focus, inert the page, or lock scrolling.

CSS owns the visual stack. `floating-presence-stack` only exposes raw state:
`--floating-presence-index`, `data-presence-index`,
`data-presence-overflowed`, `data-presence-paused`, and the transition's
`data-status`. The application decides how those values affect layout and
motion. The Vue example calculates equivalent values through bindings and uses
`useFloatingPresenceStack()` plus `useFloatingTransition()` for presence.

## Stack values

The newest surface is index `0`. The component supplies the index, while the
demo's CSS decides that a collapsed row advances by 10px and a paused stack
advances by the full 84px row-and-gap measurement.

Vue computes the same custom properties and binds the state attributes:

```vue
<ol class="toast-viewport" :data-presence-paused="paused ? '' : undefined">
  <li
    class="toast-item"
    :data-status="status"
    :data-presence-index="index"
    :style="{
      '--floating-presence-index': String(index),
    }"
  />
</ol>
```

The CSS below is the complete motion contract. Toasts are anchored to the
viewport bottom, so both entry and exit travel downward. `data-status` comes
from `FloatingTransition` or `useFloatingTransition`; it is independent from
the stack's expanded/collapsed state.

```css
.toast-viewport {
  position: fixed;
  right: max(20px, env(safe-area-inset-right));
  bottom: max(20px, env(safe-area-inset-bottom));
  width: min(360px, calc(100vw - 32px));
  height: 290px;
  pointer-events: none;
}

.toast-item {
  --floating-presence-index: 0;

  position: fixed;
  inset: auto max(20px, env(safe-area-inset-right))
    max(20px, env(safe-area-inset-bottom)) auto;
  z-index: calc(30 - var(--floating-presence-index));
  width: min(360px, calc(100vw - 32px));
  margin: 0;
  pointer-events: auto;
  transform: translateY(calc(var(--floating-presence-index) * -10px))
    scale(calc(1 - var(--floating-presence-index) * 0.04));
  transform-origin: 100% 100%;
  opacity: calc(1 - var(--floating-presence-index) * 0.14);
  transition:
    opacity 180ms cubic-bezier(0.16, 1, 0.3, 1),
    transform 220ms cubic-bezier(0.32, 0.72, 0, 1),
    display 220ms allow-discrete,
    overlay 220ms allow-discrete;
}

/* Hover or focus pauses dismissal and reveals the complete stack. */
.toast-viewport[data-presence-paused] .toast-item {
  transform: translateY(calc(var(--floating-presence-index) * -84px)) scale(1);
  opacity: 1;
}

.toast-item[data-status="initial"],
.toast-item[data-status="close"] {
  transform: translateY(120%) scale(0.98);
  opacity: 0;
}

.toast-item[data-status="close"] {
  pointer-events: none;
}

@media (prefers-reduced-motion: reduce) {
  .toast-item {
    transition-duration: 80ms;
  }
}
```

The reduced-motion rule keeps a short presence window so the transition helper
can finish removing the node, but removes most of the perceived travel. Keep
the CSS duration aligned with `exit-duration`; Vue passes the duration to
`useFloatingTransition()`.

At the lower level, `FloatingPresenceStack` emits a closed record immediately.
The Web Component adapter keeps its clone mounted until `exit-duration` ends
and then removes the record. Consumers call `add()` or `close()` and connect
`pause()` / `resume()` to the interaction policy they choose.
