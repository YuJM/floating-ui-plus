shared search controller. The demo's MSW endpoint simulates debounce,
`AbortSignal` cancellation, stale-response protection, loading/error/empty
phases, and cursor pagination.

## Application-owned search source

Both implementations import the request adapter below. The running demo uses
MSW to answer its endpoint and a generated JSON fixture for destination data;
in another application, provide an endpoint with the same response contract or
replace `searchDestinationsOnServer()` with your own request function. Neither
adapter requires a direct `@floating-ui-plus/web` installation.

## What this demo shows

- An application-owned request source with query and cursor inputs.
- Debounced requests with cancellation when the query changes.
- Stale-response protection and explicit `idle`, `loading`, `error`, `empty`,
  and `results` phases.
- Cursor-based loading of the next page.
- A `size()` middleware constraint that keeps the popup inside the available
  viewport and the result list scrollable.

The package does not choose a transport or cache library. The same composition
works with `fetch`, TanStack Query, or another request layer.

## Search configuration

```ts
query.configure({
  search: {
    source: ({query, signal, cursor}) =>
      fetchDestinationPage({query, signal, cursor}),
    getItemKey: (item) => item.id,
    debounceMs: 200,
  },
  getItemLabel: (item) => item.label,
});
```
